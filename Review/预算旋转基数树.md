# 预算旋转基数树（第 5 节）

*The Budget Rotated Trie*

---

# 它要解决什么问题

前两节（第 3、4 节）做了一件事：把哈希表的失败概率从 $1/\text{poly}(n)$ 一路压到 $1/n^{n^{1-\varepsilon}}$（双指数级小）。代价是什么？用掉了 $O(n\log n)$ 个随机比特——每个内部节点一个旋量 $r_i \in [n]$，而内部节点有 $O(n)$ 个。

第 5 节问的是反方向的问题：**如果我不在乎失败概率是 $1/\text{poly}(n)$ 还是 $1/n^{n^{1-\varepsilon}}$，我能不能在随机比特上省一大笔？**

论文引言把这两个方向称为"自然对偶"：

> *"不是试图在使用最多 $O(n)$ 随机比特的同时最小化失败概率，而是试图在维持标准 $1/\text{poly}(n)$ 失败概率的同时最小化随机比特。"*

最后拿出的结果是 $\tilde{O}(\log n)$——也就是 $O(\log n \log\log n)$ 个随机比特。作为参照：$n=2^{20}$ 时，$O(n\log n) \approx 20\text{M}$ 个比特，$\tilde{O}(\log n) \approx 86$ 个比特。

随机比特少到这个量级，有两个直接后果。第一，去随机化——如果你能用比 $\tilde{O}(\log n)$ 更少的随机比特达到 $1/n^c$ 失败概率，确定性常数时间字典就存在了（引理 6 会证明这一点）。而这是一个开放问题，所以 $\tilde{O}(\log n)$ 就是"你能省到的极限"。第二，第 6 节的简洁字典变换以预算旋转基数树为组件，随机比特少意味着简洁构造的额外开销也小。

# 相关研究

## 论文提到的

Dietzfelbinger、Gil、Matias 和 Pippenger [10] 的方法也可以在使用 $(\log n)$ 比特键的设置下实现 $O(\log n)$ 个随机比特。论文也坦承了这一点——预算旋转基数树的保证"不是新颖的"。

但论文认为预算旋转基数树的构造本身有价值，原因有二：一是展示了"逐渐增加独立性的哈希函数"的一个意想不到的用法（当伪随机数生成器而不是哈希函数）；二是在第 6 节的简洁性构造中能被当作关键组件使用。

Celis、Reingold、Segev 和 Wieder [7] 构造了负载均衡哈希族——逐渐增加独立性的哈希函数。这是预算旋转基数树能生成 $b_i$ 的理论基础。他们的构造只需要 $O(\log t \log\log t)$ 个随机比特，但评估时间是 $O(\log t \log\log t)$。后续 Meka、Reingold、Rothblum 和 Rothblum [23] 把评估时间改进到了 $O((\log\log t)^2)$。

---

# 论文提出的技术：预算旋转基数树

出发点是第 3、4 节的旋转基数树，扇出固定在 $n^\delta$（论文取 $\delta = 1/4$）。在此基础上做了三个修改。

## 直觉

整个构造的指导思想是：**把随机性从"每个节点独立生成"压缩为"用少量种子通过哈希函数派生"**。这不是一个简单的事情——如果你随便用一个哈希函数生成旋量，分析时会发现你需要很强的独立性才能保证负载均衡。但高独立性 = 更多随机比特，这就跟目标矛盾了。

论文的洞见是：**不同层级的信息对独立性的要求不同。** 球到组的分配（$a_i$）只需要 $k$ 独立就够了（$k$ 是常数，$O(\log n)$ 比特）。组内球到桶的分配（$b_i$）需要更强的独立性和负载均衡保证——但这时处理的规模已经小了（每组 $n^{1-\delta}$ 个球），而且 $b_i$ 的生成可以分摊到多次插入上。这样就把"高独立性但超常数时间评估"这个势能用分摊化解了。

---

# 技术实现

## 修改一：控制内部节点数量

在原来的旋转基数树里，只要有需要就会创建内部节点——最终节点数是 $O(n)$。

预算旋转基数树加了一条新规则：**只有当以 $x$ 为根的子树包含至少 $\Delta = \text{polylog } n$ 个元素时，才为 $x$ 创建一个真正的内部节点。** 如果某棵子树不足 $\Delta$ 个元素，这棵子树整个塞进一个动态融合节点 $z$，$z$ 作为一个"迷你字典"来代理这个内部节点的一切功能。

如果 $z$ 中的元素数量后来超过了 $\Delta$，那就真的为 $x$ 创建一个内部节点。此时球 $b$ 同时持有两个指针：一个指向真正的内部节点 $x$，一个指向融合节点 $z$（因为 $z$ 里还有之前塞进去的元素，不能丢）。

**效果**：内部节点总数 $m \leq O(n/\Delta) = n / \text{polylog } n$。旋量 $r_i$ 的总随机比特从 $O(n\log n)$ 降到了 $n / \text{polylog } n$。

> 这只是第一步——$n/\text{polylog } n$ 还是太多了（虽然比 $O(n\log n)$ 好）。后面两步才是重头。

---

## 修改二：拆开桶映射

原来的映射是 $\phi(s,c) = (c + r_s) \bmod n$。一个旋量 $r_s$ 同时决定球落在 $n$ 个桶中的哪一个。

新的映射把事情拆成两个独立的维度：

$$
\phi(s,c) = ((c + a_s) \bmod n^{\delta}) \cdot n^{1-\delta} + b_s
$$

把 $n$ 个桶组织成 $n^{\delta}$ 个**组**，每组 $n^{1-\delta}$ 个桶。映射逻辑：

- 前半截 $((c + a_s) \bmod n^{\delta}) \cdot n^{1-\delta}$ 决定球去哪个**组**。$a_s \in [n^{\delta}]$ 是组的偏移，$c$ 是孩子索引。因为对固定的 $a_s$，$c \in [n^{\delta}]$ 跑遍 $n^{\delta}$ 个值，$(c + a_s) \bmod n^{\delta}$ 是个一一映射——同一个源节点向不同组各放至多一个球。

- 后半截 $+ b_s$ 决定球在组内的哪个**桶**。$b_s \in [n^{1-\delta}]$。

**为什么这个拆分很关键？** 因为它把一个"$m$ 个节点映射到 $n$ 个桶"的大问题，拆成了一个"$m$ 个节点映射到 $n^{\delta}$ 个组"的较小问题，加上一个"每组内至多 $O(n^{1-\delta})$ 个球映射到 $n^{1-\delta}$ 个桶"的局部问题。两个问题的参数规模不同，对哈希函数独立性的要求也不同——这恰好可以被修改三分别处理。

---

## 修改三：用哈希函数生成 $a_i$ 和 $b_i$

### 生成 $a_i$：$k$ 独立就够了

令 $g: [n] \to [n^{\delta}]$ 是一个从 $k$ 独立哈希族中随机选取的函数，取 $a_i = g(i)$。$k$ 独立族可以用 $O(k \log n)$ 个随机比特指定——$k$ 是常数（比如 $k=16$），所以只要 $O(\log n)$ 个比特。而且 $g(i)$ 可以在 $O(1)$ 时间内求值。

分析则用到 [[数学工具#k-独立随机变量的尾部界]]（引理 4）。设组 $G_i$ 中的球数为 $|G_i|$。每个源节点向 $G_i$ 放球的事件是 $k$ 独立的 0-1 随机变量，总共 $O(n)$ 个球等可能分布，$\mathbb{E}[|G_i|] = O(n^{1-\delta})$。取 $t = n^{1-\delta}$，引理 4 告诉我们偏差超过 $n^{1-\delta}$ 的概率是 $n^{-\Omega(k)} = 1/\text{poly}(n)$。所以：

$$
|G_i| \leq O(n^{1-\delta}) \quad \text{以高概率成立。}
$$

### 生成 $b_i$：需要更强的工具

每组 $G_i$ 内，最多 $O(n^{1-\delta})$ 个球（来自不同源节点），要映射到 $n^{1-\delta}$ 个桶。我们需要每个桶的负载不超过 $\text{polylog } n$。

如果还用 $k$ 独立哈希：尾部界给出多项式级的概率保证。但桶的数量也是多项式的，Union Bound 之后概率就松了——你没法保证"所有桶同时不超载"。

Celis、Reingold、Segev 和 Wieder [7] 的**负载均衡哈希族** $\mathcal{H}$ 直接解决了这个问题。取 $t = n^{1-\delta}$，$h \in \mathcal{H}(t)$ 满足：

- 描述 $h$ 只需 $O(\log t \log\log t) = O(\log n \log\log n)$ 个随机比特
- 把 $t$ 个球映射到 $t$ 个桶，最大负载 $\text{polylog } t = \text{polylog } n$
- 成功概率 $1 - 1/\text{poly}(t) = 1 - 1/\text{poly}(n)$

它的核心机制是"逐渐增加的独立性"：$h$ 是 $O(\log\log t)$ 个不同独立性水平的哈希函数叠成的——低位比特需要高独立性，高位比特只需要低独立性。这样一来，总随机比特就不需要像全部高独立性那么多。

**评估时间的代价**：$h$ 的求值需要 $O((\log\log t)^2) = O((\log\log n)^2)$ 时间——不是 $O(1)$。论文把 $h$ 当**伪随机数生成器**而不是哈希函数来用：$b_i = h(i)$ 只在创建新节点时调用一次。由于修改一保证了每 $\Delta = \text{polylog } n$ 次插入才建一个新节点，且 $\Delta = \Omega((\log\log n)^2)$，$h$ 的求值时间完全被 $\Delta$ 次插入分摊掉了——建节点时花 $O((\log\log n)^2)$ 时间，摊到 $\text{polylog } n$ 次插入上，每次操作只多 $O(1)$。

---

# 正确性证明

证明分三层。

**第一层：组的大小可控。** 定义 $X_j$ = 源节点 $j$ 向组 $G_i$ 放入一个球。因为 $X_j$ 是 $g$ 的函数、$g$ 是 $k$ 独立的，这些 $X_j$ 是 $k$ 独立的 0-1 随机变量。总球数 $O(n)$，每组均匀分配，$\mathbb{E}[|G_i|] = O(n^{1-\delta})$。引理 4 → $\Pr[|G_i| > O(n^{1-\delta})] \leq 1/\text{poly}(n)$。Union bound 过 $n^\delta$ 个组 → 所有组同时满足界，概率 $1 - 1/\text{poly}(n)$。

**第二层：组内桶的负载可控。** 组 $G_i$ 内，球来自 $|S_i| \leq O(n^{1-\delta})$ 个不同源节点。每个源节点 $s$ 在组内只有一个球（修改二的关键性质），它被分配到第 $b_s = h(s)$ 个桶。因此组 $G_i$ 中第 $r$ 个桶的球数为 $|\{s \in S_i \mid h(s) = r\}|$。$h$ 来自负载均衡族 $\mathcal{H}(n^{1-\delta})$，由定义直接给出每个桶的球数 $\leq \text{polylog } n^{1-\delta} \leq \text{polylog } n$，概率 $1 - 1/\text{poly}(n^{1-\delta}) \geq 1 - 1/\text{poly}(n)$。

**第三层：全局。** 两层 Union bound 合起来：所有组不超载 + 所有组内桶不超载 → 全局所有桶的球数 $\leq \text{polylog } n$，概率 $1 - 1/\text{poly}(n)$。每个桶用动态融合节点实现 → 每个操作 $O(1)$ 最坏时间。

随机比特：$g$ 需要 $O(\log n)$，$h$ 需要 $O(\log n \log\log n)$。总计 $O(\log n \log\log n) = \tilde{O}(\log n)$。

---

# 优越性：为什么 $\tilde{O}(\log n)$ 是最优的

引理 6 的论证极其简单，但结论很强。

**引理 6**：如果存在一个使用 $c\log n$ 随机比特、失败概率小于 $1/n^c$ 的哈希表，那么存在一个确定性常数时间字典。

**证明**：设哈希表的 $c\log n$ 个随机比特为 $R$。把所有比特固定为 $0$，得到一个确定性字典 $D$。假设 $D$ 在某个操作序列上不是常数时间的。原哈希表有 $2^{c\log n} = n^c$ 种随机比特取值，每种等可能。因此原哈希表在这组操作上超时的概率 $\geq 1/n^c$。但这跟"失败概率 $< 1/n^c$"矛盾。□

这个论证说明了什么？**如果你想把随机比特数压到 $c\log n$ 以下，你就必须接受 $\geq 1/n^c$ 的失败概率**——除非有人造出了确定性常数时间字典。而后者是一个开放问题，大家普遍认为短时间内做不到。

因此，$\tilde{O}(\log n)$ 个随机比特、$1/\text{poly}(n)$ 的失败概率——这是你在"不解决大开放问题"的前提下能达到的最好结果。

---

# 值得注意的地方

**$h$ 的角色转换**值得单拎出来说。一个因为评估时间太长而被认为不适合用于常数时间哈希表的哈希族，被论文当成"建节点时才跑一次的随机数生成器"——换个用法，缺点就消失了。这种"把一个工具从它原本的语境里拿出来重新定义它的用途"的做法，在理论计算机科学里经常是好结果的来源。

---

# 总结

预算旋转基数树用一个极小的随机种子（$\tilde{O}(\log n)$ 比特）驱动整个哈希表，所有操作以高概率 $O(1)$。它本质上是一套"随机比特压缩"方案——通过把随机性的生成推迟、分摊、分级（$k$ 独立管粗粒度的组分配，负载均衡哈希管细粒度的桶内分配），在不牺牲操作时间的前提下把随机比特消耗压到了理论下界附近。
