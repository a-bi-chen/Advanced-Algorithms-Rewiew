## 一、与放大旋转基数树的区别

预算旋转基数树在 [放大旋转基数树](放大旋转基数树_伪代码.md) 的基础上做了三个关键修改，目标是将随机比特数降至 $\tilde{O}(\log n)$：

| 修改项 | 放大旋转基数树（§4） | 预算旋转基数树（§5） |
|:--:|:--|:--|
| **球到桶映射** | $\phi(s,c) = (c + r_s) \bmod n$ | $\Psi(s,c) = ((c + a_s) \bmod n^\delta) \times n^{1-\delta} + b_s$ |
| **节点创建条件** | 始终创建 | 仅当子树键数 $\geq \Delta = \text{poly}\log n$ 时才创建 |
| **$a_s$ 的生成** | 真随机（$O(\log n)$ 比特/节点） | $k$-独立哈希 $g(s)$（$O(\log n)$ 总比特） |
| **$b_s$ 的生成** | 真随机（$O(\log n)$ 比特/节点） | 负载均衡哈希 $h(s)$（$O(\log n \log\log n)$ 总比特） |
| **随机比特总数** | $O(n \log n)$ | $\tilde{O}(\log n)$ |
| **失败概率** | $1/n^{n^{1-\epsilon}}$ | $1/\text{poly}(n)$ |

## 二、数据结构定义

```
常量:
    n       : 当前键值对数量
    δ       : 扇出指数，取 δ = 1/4
    fanout  : n^δ
    Δ       : 子树的键数阈值 = polylog(n)（也是桶容量上界）
    k       : 哈希独立性参数，为足够大的偶数常数（如 k = 10）

全局变量:
    A       : 大小为 n 的数组，每个元素 A[j] 是一个动态融合节点（容量 Δ）
    m       : 内部节点数，m ≤ n/Δ = n/polylog(n)（因为延迟创建）

    // ---- 哈希函数（全局种子） ----
    g       : k-独立哈希函数 g: [n] → [fanout]（仅需 O(log n) 随机比特）
    h       : 负载均衡哈希函数 h: [m] → [n^{1-δ}]（需 O(log n loglog n) 随机比特）

    // ---- 节点级变量（从全局哈希派生） ----
    a[i]    : 节点 i 的组选择量 = g(i) ∈ [fanout]
    b[i]    : 节点 i 的桶内偏移量 = h(i) ∈ [n^{1-δ}]
```

## 三、核心映射（新）

```
// 桶被划分为 fanout 个组 G_1, G_2, ..., G_{fanout}，每组大小 n^{1-δ}
// 组 G_i 包含桶: i × n^{1-δ} 到 (i+1) × n^{1-δ} - 1

FUNCTION Ψ(s, c):
    // s: 源节点编号, c: 孩子索引 ∈ [fanout]
    group  ← (c + a[s]) mod fanout         // 随机组 (0 ≤ group < fanout)
    offset ← b[s]                          // 组内偏移 (0 ≤ offset < n^{1-δ})
    RETURN group × n^{1-δ} + offset        // 全局桶编号 (0 ≤ result < n)
```

### 映射的关键性质

- 同一源节点 $s$ 最多向每组 $G_i$ 分配**一个球**（因为 $c$ 取遍 $[n^\delta]$ 时，$(c + a_s) \bmod n^\delta$ 是一个排列——恰好覆盖每组各一次）
- $a_s$ 决定"球去哪个组"（粗粒度），$b_s$ 决定"球去组内哪个桶"（细粒度）
- 组内不会有两个球来自同一源节点，消除了同源冲突

## 四、节点的延迟创建

```
// 仅当子树包含 ≥ Δ 个键时才创建内部节点
// 否则将子树的所有键存储在动态融合节点中

CLASS LazyInternalNode(i):
    FIELD state : 枚举 { PROXY, ACTIVE, HYBRID }

    // PROXY:   子树键数 < Δ，所有键存储在代理融合节点 proxy 中
    // ACTIVE:  子树键数 ≥ Δ，已创建完整的内部节点结构
    // HYBRID:  曾经是 PROXY，增长到 ≥ Δ 后转为 HYBRID
    //          此时同时持有 proxy 和 activeNode 的指针

    FIELD proxy      : 动态融合节点（容量 Δ），PROXY/HYBRID 状态时使用
    FIELD activeNode : 指向孩子子树的指针数组，ACTIVE/HYBRID 状态时使用
    FIELD keyCount   : 子树中的键总数

    FUNCTION GetChild(c):
        IF state = PROXY THEN
            // 子树尚未展开，所有键在 proxy 中
            RETURN NIL
        ELSE IF state = ACTIVE THEN
            RETURN BucketLookup(i, c)         // 通过 Ψ 映射到桶
        ELSE // HYBRID
            result ← BucketLookup(i, c)
            IF result = NIL THEN
                result ← proxy.Lookup(c)      // 也在 proxy 中查
            RETURN result
```

## 五、桶操作（使用新映射 Ψ）

```
FUNCTION BucketInsert(s, c, pointer):
    j ← Ψ(s, c)
    A[j].Insert(s, pointer)

FUNCTION BucketLookup(s, c):
    j ← Ψ(s, c)
    RETURN A[j].Lookup(s)
```

## 六、查询操作

```
FUNCTION Query(rootKey):
    (j_1, ..., j_d) ← SplitIntoDigits(rootKey, fanout)
    currentNodeID ← 1

    FOR k = 1 TO d DO:
        node ← GetNode(currentNodeID)
        IF node.state = PROXY THEN
            RETURN node.proxy.LookupValue(rootKey)   // 子树未展开

        ptr ← BucketLookup(currentNodeID, j_k)
        IF ptr = NIL AND node.state = HYBRID THEN
            ptr ← node.proxy.Lookup(j_k)             // 尝试 proxy

        IF ptr = NIL THEN RETURN NIL
        (nextNodeID, _) ← ptr
        currentNodeID ← nextNodeID

    RETURN GetValue(currentNodeID)
```

## 七、插入操作

```
FUNCTION Insert(rootKey, value):
    (j_1, ..., j_d) ← SplitIntoDigits(rootKey, fanout)
    currentNodeID ← 1

    FOR k = 1 TO d-1 DO:
        node ← EnsureNode(currentNodeID)
        node.keyCount ← node.keyCount + 1

        IF node.state = PROXY THEN
            node.proxy.Insert(j_k, NIL)       // 标记孩子存在
            IF node.keyCount ≥ Δ THEN
                PromoteNode(node)             // 子树键数达标，展开为内部节点
            CONTINUE

        // ACTIVE 或 HYBRID 状态
        ptr ← BucketLookup(currentNodeID, j_k)
        IF ptr = NIL THEN
            newID ← AllocateLazyNode()
            BucketInsert(currentNodeID, j_k, (newID, 0))  // 预算版本无 r_i
            ptr ← (newID, 0)
        (nextNodeID, _) ← ptr
        currentNodeID ← nextNodeID

    SetValue(currentNodeID, value)
```

## 八、节点提升（Proxy → Active）

```
FUNCTION PromoteNode(node):
    // 将 PROXY 状态的节点提升为 ACTIVE
    // 初始化 a[nodeID] 和 b[nodeID]

    nodeID ← node.id
    a[nodeID] ← g(nodeID)                     // k-独立哈希，O(1) 时间
    b[nodeID] ← h(nodeID)                     // 负载均衡哈希，O((loglog n)^2) 时间

    // 将 proxy 中已有的孩子条目迁移到桶中
    FOR EACH (childDigit, _) IN node.proxy DO:
        newChildID ← AllocateLazyNode()
        BucketInsert(nodeID, childDigit, (newChildID, 0))

    node.state ← ACTIVE

    // 注：h(nodeID) 的 O((loglog n)^2) 开销分摊到触发本次提升的 Δ 次插入上
    // 因为 Δ = polylog(n) = Ω((loglog n)^2)，摊销后每次插入 O(1)
```

## 九、初始化

```
FUNCTION Initialize():
    // 全局哈希函数（一次性随机种子）
    g ← RandomKwiseHash(k, fanout)                    // O(log n) 随机比特
    h ← RandomLoadBalancingHash(n^{1-δ})               // O(log n loglog n) 随机比特

    // 桶数组
    FOR j = 1 TO n DO:
        A[j] ← NewDynamicFusionNode(Δ)

    // 根节点（延迟创建）
    m ← 1
    root ← LazyInternalNode(1)
    root.state ← PROXY
    root.keyCount ← 0
```

## 十、哈希函数的初始化时机

```
注：a[i] 和 b[i] 的初始化发生在节点 i 的 PromoteNode 过程中：
  - a[i] = g(i)：评估 k-独立哈希函数 g，O(1) 时间
  - b[i] = h(i)：评估负载均衡哈希函数 h，O((loglog n)^2) 时间

这样做的原因：
  1. 节点总数 m ≤ n/polylog(n)，不会为所有 m 个节点都计算 a_i 和 b_i
     （只有被 Promote 的节点才计算，而被 Promote 的节点数 ≤ m）
  2. 即使计算所有 m 个 a_i 和 b_i 的总成本 = m × O((loglog n)^2)
     ≤ O(n/polylog(n) × polylog(n)) = O(n)，可接受
  3. 对每个节点而言，O((loglog n)^2) 的初始成本被 Δ = Ω((loglog n)^2) 次
     插入分摊，最终每个操作的摊销时间仍为 O(1)
```

## 十一、复杂度分析

| 指标 | 值 | 说明 |
|:--:|:--:|------|
| **查询时间** | $O(1)$ 以高概率 | 深度 O(1)，每层走 Ψ 映射 + 融合节点查找 |
| **插入时间** | $O(1)$ 摊销 | PromoteNode 的 O((loglog n)²) 分摊到 Δ 次插入 |
| **空间** | $O(n \log n)$ 比特 | 线性空间 |
| **随机比特** | $O(\log n \log\log n)$ | g: O(log n), h: O(log n loglog n) |
| **失败概率** | $1/\text{poly}(n)$ | 以高概率成功 |

**最优性**：[引理 6](引理6证明.md) 证明，若使用 $c \log n$ 随机比特且失败概率 < $1/n^c$，则存在确定性常数时间字典。
