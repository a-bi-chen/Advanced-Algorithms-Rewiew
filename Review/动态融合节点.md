# 动态融合节点

*Dynamic Fusion Node — Pǎtraşcu & Thorup, FOCS 2014 [30]*

---

## 介绍

**动态融合节点**（Pǎtraşcu & Thorup, FOCS 2014）维护一个 $k \leq w^{1/4}$ 个 $w$-位整数的动态集合，仅用标准字操作（加减乘、位运算、移位），所有操作常数时间：

$$\boxed{\text{insert, delete, predecessor, successor, rank, select} \quad\text{全部}\quad O(1)}$$

空间 $O(k)$ 个字，线性。

"动态"是相对于 Fredman-Willard 的**静态融合节点**（FW93）：后者查询 $O(1)$，但更新 $O(k^4)$。动态融合节点的更新也是常数时间——这是本质区别。

---

## 二、它解决了什么

Ajtai, Komlos, Fredman [AFK84] 在 cell-probe 模型里能用自定义字操作常数时间处理小集合，但他们自己承认：*"我们的查询算法并不现实，搜索 trie 在实际上超过常数时间。"*

Fredman-Willard 的静态融合节点用标准操作做到了常数时间查询，但更新是 $O(k^4)$。Pǎtraşcu-Thorup 彻底解决了这个问题。两个核心突破：

1. **无关位匹配**：在压缩键中引入 "?"（don't care），使压缩 trie 搜索可被常数时间模拟，且压缩可增量更新
2. **完美动态压缩**：压缩键精确 $\ell \leq k$ 位（FW93 是松散的 $O(k^3)$），支持常数时间增量更新

---

## 三、基础设定

集合 $S$ 存在无序数组 $KEY$（$k$ 个 $w$-位槽）加一个字 $INDEX$：

$$\boxed{\text{select}(i) = KEY[\langle INDEX \rangle_i^{\lceil\lg k\rceil}]}$$

$INDEX$ 共 $k\lceil\lg k\rceil \ll w$ 位，塞进一个字。空闲槽用位图 $bKEY$ 管理，$\text{msb}(bKEY)$ 给第一个空位。

> **引理 1（FW93）** 若 $mb \leq w$，给定排序好的 $m$ 个 $b$-位数 $A$，可在常数时间内求任意 $x$ 的 $\text{rank}(x, A)$。

做法：乘法造 $x^m$（$m$ 份拷贝）→ 减法做并行逐字段比较 → $\text{msb}$ 取最大真值。这是整个构造反复调用的原子操作。

---

## 四、核心机制

动态融合节点要同时解决两件事：① 常数时间搜压缩 trie；② 键变化时维护搜所需的数据。

### 4.1 无关位匹配

对每个键 $y \in S$ 构造 $y^?$（字符集 $\{0,1,?\}$）：

- 若位置 $j$ 是**重要位**（$\exists z \in S,\; \text{msb}(y \oplus z) = j$，即 trie 在此有分支），$\langle y^? \rangle_j = \langle y \rangle_j^1$
- 否则 $\langle y^? \rangle_j = \;?$（无关）

（压缩 trie 将二叉 trie 中所有度为 1 的链压缩为单条"捷径边"；仅保留度 ≥ 2 的**分支节点**和叶子。节点 $u$ 的**层级** $\ell(u)$ 是它在原 trie 中的深度——即该节点比较的是键的第 $\ell(u)$ 位。）

查询键 $x$ **匹配** $y^?$ 当且仅当在所有非 "?" 位上两者一致。这恰好等价于：在 $S$ 的压缩 trie 中搜 $x$ 会到达 $y$。

> **观察 2** 设 $y^?$ 匹配 $x$（$y \neq x$），$j = \text{msb}(x \oplus y)$：
> - $x < y \implies x \land (1^{w-j}0^j)$ 匹配 $x$ 的**后继**
> - $x > y \implies x \lor (0^{w-j}1^j)$ 匹配 $x$ 的**前驱**

**直觉**：$y^?$ 在位置 $j$ 是 "?"（$j$ 处无分支节点，被一条捷径边跳过）。$x \land (1^{w-j}0^j)$ 把 $j$ 及以下位清零，从捷径下端始终走 0-子 → 到达子树最小键（后继）。$x \lor (0^{w-j}1^j)$ 同理走 1-子 → 最大键（前驱）。

**意义**：两次匹配找到前驱/后继。静态融合节点需要预计算 $k \times k \times 2$ 的 $RANK$ 表——动态融合节点用第二次匹配省掉了这张表，更新时不需要维护它。

### 4.2 BRANCH 和 FREE 矩阵

如何在常数时间内**并行**为所有键做匹配？维护两个 $k \times k$ 位矩阵（各 $k^2 \leq \sqrt{w}$ 位，常数个字）：

设 $y$ 排名 $i$，重要位 $c_h$（压缩后位置 $h$）：

- 若 $\langle \hat{y}^? \rangle_h \neq \;?$：$\langle BRANCH \rangle_{i,h} = \langle \hat{y} \rangle_h^1$，$\langle FREE \rangle_{i,h} = 0$
- 若 $\langle \hat{y}^? \rangle_h = \;?$：$\langle BRANCH \rangle_{i,h} = 0$，$\langle FREE \rangle_{i,h} = 1$

对查询键 $x$，将 $\hat{x}$ 复制 $k$ 份得 $\hat{x}^k$（一个乘法）。计算：

$$\boxed{\text{match}(x) = \text{rank}\big(\hat{x},\; BRANCH \lor (\hat{x}^k \land FREE)\big)}$$

$BRANCH \lor (\hat{x}^k \land FREE)$ 的含义：关心位取键自己的值（$BRANCH$），无关位用 $x$ 的对应位填充（$\hat{x}^k \land FREE$）。这为每个键 $y$ 并行生成了 $\hat{y}^{\hat{x}}$——一份"从 $x$ 视角看到的 $y$ 的压缩键"。在排序好的 $\hat{y}^{\hat{x}}$ 中找 $\hat{x}$ 的 rank，就是匹配键的索引。

> **为什么 $\hat{y}^{\hat{x}}$ 是排序好的？** 因为 $x$ 的位对所有键的填充位置一致，不会在已有键之间引入新顺序：$y < z \iff \hat{y}^{\hat{x}} < \hat{z}^{\hat{x}}$。

### 4.3 完整的 rank 计算

1. $i = \text{match}(x)$，$y = KEY[\langle INDEX \rangle_i^{\lceil\lg k\rceil}]$
2. 若 $x = y$，返回 $i$
3. $j = \text{msb}(x \oplus y)$
4. $i_0 = \text{match}(x \land (1^{w-j}0^j))$，$i_1 = \text{match}(x \lor (0^{w-j}1^j))$
5. $x < y$ 则返回 $i_0-1$，$x > y$ 则返回 $i_1$

有了 rank，$\text{predecessor}(x) = \text{select}(\text{rank}(x)-1)$，$\text{successor}(x) = \text{select}(\text{rank}(x))$。

---

## 五、更新操作

### 5.1 插入

插入前先跑 $\text{rank}(x)$ 确认 $x \notin S$，此时已得到分叉位 $j = \text{msb}(x \oplus y)$ 和受影响键范围 $[i_0, i_1]$。

**若 $j$ 是新的重要位**（排名 $h$）：先在 BRANCH/FREE 中插入列 $h$（所有 $\geq h$ 的列左移一位），新列初始全无关（$FREE$ 列全 1，$BRANCH$ 列全 0）。然后修正 $[i_0, i_1]$ 行在列 $h$ 的值（这些键在 $j$ 位的值是确定的，等于匹配键 $y$ 在 $j$ 位的值）。列的插入和行范围的修正全是位掩码操作：用 $M_h = (0^{k-1}1)^k \ll h$ 选列，$M^{i_0:i_1}$ 选行，移位+逻辑运算，常数时间。

**若 $j$ 已是重要位**：只插行不插列。

然后插入 $\hat{x}^?$ 对应的行（排名 $r = \text{rank}(x)$）：所有 $\geq r$ 的行下移。新行内容：
- 列 $0..h-1$：全 "?"（$FREE$ 全 1，$BRANCH$ 全 0）
- 列 $h$：$\langle x \rangle_j^1$（$FREE_h = 0$，$BRANCH_h = \langle x \rangle_j^1$）
- 列 $h+1..k-1$：从匹配键 $\hat{y}^?$ 复制

同时更新 $KEY$ 和 $INDEX$（找空槽、移位 $INDEX$ 字段）。删除是逆操作。

---

## 六、完美动态压缩

BRANCH/FREE 操作的是**压缩键** $\hat{x}$（只含重要位）。不压缩的话 $k \times w$ 位的矩阵远超单字容量。

FW93 的压缩有 $O(k^3)$ 位且不能增量更新。Pǎtraşcu-Thorup 的压缩：精确 $\ell \leq k$ 位，支持常数时间增量更新。分三步：

**打包**：块大小 $b = w/k^2$。为每块贪心找移位 $s_i < k^2/2$，使各块重要位移位后不重叠（$\leq k$ 个设置位 vs $k^2/2$ 个候选移位，必成功）：

$$\mu(x) = \sum_i \bigl(\langle (x \land B) \rangle_i^b \ll s_i\bigr)$$

结果 $\mu(x)$ 长 $2b = 2w/k^2$ 位。奇偶块分开乘避免进位干扰。

**重排**：$\mu(x)$ 中重要位还不连续。用 $LSHIFT$ 字（$k$ 个 $4b$ 位字段，存位移信息），乘 $\mu(x)$ 后每位"弹"到字段首，掩码只留首位。

**收集**：再乘 $S_1$（预计算常数），把所有重要位收集到连续位置 → $\hat{x}$。三步共三次乘法。

**动态维护**：新重要位出现时插入 $C$ 数组（存 $c_h$ 值），算出它在 $\mu(x)$ 中的位置 $\mu_i$，在 $LSHIFT$ 中插入对应字段。若块移位需调整，用常数 $S_0$ 并行搜新移位（减法借位技巧做碰撞检测）→ 更新 $LSHIFT$ 中受影响字段。全是位操作和乘法，常数时间。

---

## 七、复杂度与对比

| 指标 | 静态融合节点 (FW93) | 动态融合节点 (PT14) |
|:---|:---|:---|
| 查询 | $O(1)$ | $O(1)$ |
| 更新 | $O(k^4)$（重建） | $O(1)$（增量） |
| 压缩长度 | $O(k^3)$（松散） | $\ell \leq k$（完美） |
| 压缩更新 | 不支持 | $O(1)$ 增量 |
| 前驱/后继 | 需 $RANK$ 表 | 两次 match，无需表 |
| 容量 | $k \leq w^{1/6}$ | $k \leq w^{1/4}$ |

$k = w^{1/4}$ 的约束来自：BRANCH/FREE 各 $k^2 \leq w^{1/2}$ 位，两矩阵总和 $\ll w$——必须塞进常数个字。

根本差异在**无关位**：静态融合节点中压缩键每位对所有键都是确定的——压缩参数依赖整个键集合，一变就得重建。无关位将"搜索结构"和"键的具体值"解耦——更新只影响直接相关的行/列。
