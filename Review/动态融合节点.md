# 介绍

动态融合节点（Dynamic Fusion Node）这个概念来自 Pǎtraşcu 和 Thorup 的论文 [30]，那篇论文主要做的是动态整数集合的 rank、select 和 predecessor 查询。但这个方向上的早期工作要追溯到 Fredman 和 Willard 的融合树 [15]——融合节点这个叫法就是从那儿来的。

在本文里用到的只是 [30] 中一个很具体的部件：一个**确定性的常数时间字典**，可以存最多 $\Delta = \text{polylog } n$ 个键值对，每个键 $\Theta(\log n)$ 比特，且空间是线性的。

原论文是这么说的：

> *"我们简单地将 $A$ 的每个条目实现为一个动态融合节点（dynamic fusion node）[30]，这是一个确定性的常数时间线性空间字典，能够一次存储最多 $\Delta = \text{polylog } n$ 个键/值对。"*

---

# 在本文中的作用

旋转基数树把 $m$ 个内部节点的数组 $A_1, A_2, ..., A_m$ 折叠进一个全局数组 $A$。同一个桶 $A[j]$ 可能被好几个节点的指针命中。

怎么处理这个冲突？把 $A$ 的每个桶实现为一个动态融合节点。桶里存的是键值对，键是源节点编号 $i$，值分两种情况：

- 指针指向另一个内部节点 $A_{i'}$ 的，存 $(i, (i', r_{i'}))$
- 指针直接指向某个值（到叶子了）的，存 $(i, p)$

第 3 节证明了每个桶的球数以高概率不超过 $\Delta = \text{polylog } n$，所以桶容量设成 $\text{polylog } n$ 完全够用。万一真超过了——那就是第 4 节溢出树 $Q$ 要管的事了。

---

# 为什么一定要用确定性的？

论文引言里有一个背景值得注意：

> *"一个核心的开放问题是是否存在一个确定性的常数时间字典。这个方向上一个引人注目的成功是 Pǎtraşcu 和 Thorup 的动态融合节点（dynamic fusion node）[30]……为非常小的键集合——即最多包含 $\text{polylog } n$ 个键、每个键 $\Theta(\log n)$ 比特的集合 $S$——构造了一个确定性的常数时间字典。"*

换句话说，确定性常数时间字典本身就是一个很难的问题，动态融合节点是目前少数能在这个方向上拿出结果的构造。

回到本文。在旋转基数树（第 3 节）和放大旋转基数树（第 4 节）中，随机性只来自每个节点的旋量 $r_i$。如果桶内部的字典也要靠随机化，等于在旋量这一层随机性之外又加了一层——两个随机源叠在一起，分析起来就不是一个 Chernoff 界或者 McDiarmid 不等式能解决的了。

反过来，因为融合节点是确定性的，第 3 节和第 4 节的概率分析可以全部聚焦在一个变量上：**$r_i$ 的取值导致桶溢出的概率有多大**。第 3 节用 Chernoff 界给出了 $1/2^{\text{poly}\log n}$ 的上界，第 4 节用 McDiarmid 不等式进一步压到 $1/n^{n^{1-\varepsilon}}$。如果桶本身还有失败概率，这个链条从一开始就断了。

---

# 总结

这个融合节点就是解决折叠冲突的——桶里可能塞了来自不同节点的好几个指针，每个桶自己用一个确定性微型字典把它们按源节点编号 $i$ 分开存。

因为是确定性的，它不会引入额外的随机失败概率。旋转基数树的分析只需要关注"桶容量够不够"，不需要操心桶里面会不会出问题。这也是这篇论文能把失败概率一路压到 $1/n^{n^{1-\varepsilon}}$ 的前提之一。

> **引用**：[30] Mihai Pǎtraşcu and Mikkel Thorup. Dynamic integer sets with optimal rank, select, and predecessor search. FOCS 2014.
